# 读数 2026-11-12：0.0.23–0.0.29（车厢批次）是否有效

免费流量跑完后的读数。免费额度已用尽（组织终身 3 次），只剩付费 $20 / 3 天 / 约 50 次游玩。

## 方法与它的边界

Playgama 的遥测只开放预聚合视图，**没有原始事件导出**。遥测指南的原话：「The tools expose preaggregated views, not raw events. Do not try to reconstruct a raw export by exhaustively fetching every event, field, time bucket and session.」`get_game_telemetry_session_facts` 也写明是 "preaggregated and pseudonymized"，不是完整用户历史。所以本地没有、也不会有一份可以反复重算的原始数据集；每次要新角度，只能再查一次。本文件存在的理由就是：**把查过的数字留下来，别再查第二遍。**

对比取两个干净的单版本日：**11-10 全天 = 0.0.21（无车厢）**，**11-12 00:00–07:30 = 0.0.29（全部改动）**。11-11 版本混杂，丢弃。两天的 `load.runs` 合计分别是 25 和 2，即各只有 1 个回头客，两组都是新玩家，可比。

车厢本身成立：74 个点过屏幕的人里 41 个（55%）见到第一次选车厢，28 个到第 3 次，8 个到第 7 次；四种被手挑的次数相当（电弧 22 / 冰霜 23 / 等离子 22 / 导弹 21），自动选只有 3 个会话。

## quit_wave_10 的现场（卡在 wave 5–10 之间离开的人）

字段含义见 `src/sim/world.ts:129`：`fence` 栅栏剩余 %，`pick`=1 表示走时车厢卡牌正开着，`quiet` 距上次输入的秒数。

**结论：这批人不是被打死的。** 两个版本里栅栏都在 90% 上下，11 个会话里最低 83%，没有一个接近失败。他们是在一场稳赢的仗里、约 3 分钟时、手里攥着金币、旁边还有一张能买的卡，直接走了。

这不是车厢带来的新问题——0.0.21 的 3 个会话是同一副样子。车厢只是让同样的进度多花了时间（到相近波次 169 s → 202 s）。

所以 wave 5→10 掉的那一截，**病因是「第一关太长、赢得没有张力」，不是难度墙，也不是缺多发**。方向应当是缩短第一关或给这一局一个看得见的终点，而不是加强度或降难度。

样本极小（3 vs 8 个会话），把它当作方向而非定论。
