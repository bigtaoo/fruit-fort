# 低流量下怎么读遥测、怎么改

每个版本只有 10～30 个真实新玩家时的分析方法。写于 2026-11-20，来自 swarm-orbit 0.0.17～0.0.38 的教训。本文不依赖具体游戏，其他项目可直接套用。

## 一句话

**20 个人不足以「测量」改进，但足以「定位」问题。** 少看平均数，多读每个玩家的记录；没改过的部分把各版本的数据合起来看；只做大改动，并用离改动最近的那一步来衡量效果。

## 1. 先认清 20 个人能看出什么

比例的 95% 区间（Wilson）：

| 观察到 | 真实值大概在 |
|---|---|
| 10/20（50%） | 30%～70% |
| 4/20（20%） | 8%～42% |
| 2/20（10%） | 3%～30% |
| 16/20（80%） | 58%～92% |
| 55/110（50%） | 41%～59% |
| 22/110（20%） | 14%～28% |

- 每组 20 人时，两个版本要差约 40 个百分点才能区分开，比如 30% 对 70%。差 10 个百分点根本看不出来。
- **平均时长在这个人数下没法用。** 一个挂机 80 分钟的标签页或一个测试账号，就能让平均数翻倍。swarm-orbit 卡片上的「12:34」和「8 分钟」都是这样来的，中位数其实一直是 60～90 秒。
- 中位数，以及「超过 N 分钟的人占多少」，比平均数稳，但每组 20 人时仍然只能看出很大的变化。

## 2. 先把人数算对

- **只算新玩家**（以前没玩过的），而且**只算点过屏幕的人**。没点就走的人另算，那是加载或第一印象的问题。
- **排除机器人。** 它们的特征很固定：软件渲染（SwiftShader）、固定秒数内点击、从不购买、在同一个时间点离开、fps 很低。先按这些特征列出可疑会话，再整组剔除。
- **排除自己和测试账号。** 比如公开之前就有的会话，或者一个人打了好几个小时、把内容全部打通。
- **排除挂机。** 时长很长但几乎没有进度的会话，不能算作「玩了很久」。
- 不要自己打开线上游戏页去「看一眼」，这会增加启动次数、拉低平均时长。

## 3. 每个玩家都是一条记录：读，不要只算

把每个新玩家的会话排成一行，列出：时间点、走到哪一步、最后一个事件、离开时在哪个界面、离开前做了什么（输了、赢了、在买东西、什么都没做）。

20 行就能看出规律，比如：
- 12 个人都停在第一次引导之前。
- 赢下战斗的人在第 6～7 波离开，围栏还剩 90%（swarm-orbit 11-12 的真实发现，据此把 1-1 缩到了 6 波）。
- 打得久的人都是在连输之后离开。

**一种情况出现在 3 人以上就是线索，出现在一半以上的人身上就是结论。** 这种读法不需要统计显著性。

## 4. 漏斗：把开头拆成步骤

从「加载完成」到「第一次看到结算或奖励」拆成 5～8 步，每一步都要有对应事件。例如：加载完成 → 第一次点击 → 引导完成 → 第一次击杀 → 第一次购买 → 第 2 波 → 第 3 波 → 第一张结算卡。

- 先看**流失最多的那一步**，只改那里。
- 埋点时必须做到：
  - 每一步有自己的事件，而且带时间。
  - 有定期心跳，用来算停留时长。
  - 离开时发一个退出事件，带上当前所在的界面或步骤。
  - 关键事件不要等到玩家离开某个界面才发。swarm-orbit 的 `run_end` 就是在离开结算卡时才发，所以结算卡上直接关页面的人不会被记到，需要再用退出事件补回来。
- 事件不够细时，先发一个**只加埋点、不改玩法**的版本，等下一批玩家进来。

## 5. 没改过的部分，把各版本的数据合起来

开头几分钟如果几个版本都没动过，那几个版本的新玩家就可以合在一起算这一段的漏斗。swarm-orbit 的开场从 0.0.31 到 0.0.38 基本没变，合起来约 110 人。人数到了 100 左右，每一步的比例误差大约是 ±9 个百分点，已经能用了。

由此得出一条做法：**被测的那一段一次只改一处，其他部分不要动。** 后面的内容随便改，因为不影响开头的读数。

## 6. 怎么改、怎么判断改得有没有用

1. **只做能带来大变化的改动。** 目标应该是让某一步的流失从 50% 降到 20%，而不是改善 5%。20 人看不出的改进，在流量小的阶段也不值得追。
2. **用离改动最近的那一步来判断。** 改了引导就看引导完成率，不看整局时长，因为离改动越远，噪声越多。
3. **改之前先写下预期**，比如：「这一步的通过率从 40% 涨到 70% 以上算有效，不到 50% 算无效。」数据进来后按事先写的标准判断，不要事后再找解释。
4. **改动要针对多数人看得到的部分。** swarm-orbit 做了很多中后期内容（车厢、卡牌、循环、难度），中位数一直没动，因为一半的人在第一分钟就离开了，根本没看到这些内容。先看清楚多数人停在哪里。
5. **不要用机器人或自己手打的结果代替真实玩家。** 它们代表的是另一类玩家，只能用来检查有没有 bug、平衡有没有被改坏。

## 7. 免费或便宜的真人信息

- **看 5 个陌生人实际玩一遍**，往往比读 100 条遥测更快找到开场的问题，因为能看到他们在哪里犹豫、看不懂什么。可以找朋友或同事，或者发到 r/playmygame、itch.io。规则只有一个：什么都不解释，只看前 60 秒他们做了什么、在哪里停下。
- 发行平台自带的试玩工具，或者首发时的免费流量（据说 Poki、CrazyGames 有，条款未核实）。
- 买量时，留着用在**验证一个已经定位好的大改动**上，不要花在「看看这版怎么样」上。

## 8. 每次读数据的检查清单

- [ ] 时间范围从版本上线时刻算起（UTC）
- [ ] 只算新玩家、点过屏幕的人；机器人、测试账号、挂机已剔除，并写明剔除了几个
- [ ] 列出每个人的记录，读出 3 人以上重复出现的情况
- [ ] 漏斗每一步的人数；没改动的部分合并多个版本来看
- [ ] 改动对应的那一步，对照改之前写下的标准
- [ ] 平均时长只记录，不用来做决定
- [ ] 结论写清楚是「线索」（3～4 人）还是「结论」（多数人，或合并后的大样本）
